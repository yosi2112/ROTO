# Video backends and ASW (q003)

The default remains 8 colours. `/256` explicitly requests normal-resolution PEGC
packed pixels; `/8` selects the original 8-colour image. High-resolution machines
are detected automatically. This is compatibility support, not an EGC blitter demo.

| Hardware | Detection | Rendering |
|---|---|---|
| Original normal resolution | fallback | A800/B000/B800 segments, 80-byte pitch |
| GRCG | BIOS 0000:054C bit 1 | TDW clear of all four planes, direct planar row copies |
| EGC | BIOS 0000:054D bit 6 | protected mode-register sequence selects GRCG compatibility |
| PEGC 8-colour | normal compatibility | same planar renderer |
| PEGC 256-colour | `/256` and BIOS 0000:045C bit 6 | 640x400 packed pixels, A8000 32KB aperture, E000:0004 bank register |
| High-resolution | BIOS 0000:0501 bit 3 | C0000-DFFFF shared 128KB aperture, A4 plane mask; 140-byte pitch |

High-resolution uses INT 1Dh GINIT/GSTART/GSTOP/GTERM with a dedicated, paragraph
aligned 380h-byte UCW and a far-return callback. It never invokes normal graphics
INT 18h functions 40h-42h. Text visibility still uses INT 18h 0Ch/0Dh. The 640x400
image starts at (240,175) in the 1120x750 screen. All four planes are cleared and
only B/R/G are subsequently written. Advancing the segment by 35 paragraphs per
logical row avoids the 64KB wrap at lower screen positions. A4/A6 are never used
as page selectors on high-resolution machines. A failed GINIT exits before text
is hidden; a failed GSTART runs cleanup and returns DOS errorlevel 1.

PEGC initializes all 256 B3/R3/G2 palette entries and uses a separate 64x64
texture containing all 256 indices. Each 640-byte scanline is split at a 32KB bank
boundary. Only 256000 visible bytes are touched; the last bank's unused tail is
preserved. Packed output is single-page. Exit resets bank selectors, disables
256 colours and restores text display. High-resolution 256-colour add-on boards
and third-party accelerators are outside this implementation.

Sources checked (2026-09-17):

- Local emulator `E:/source/src/vm/pc9801/display.cpp`: high-resolution plane masks,
  128KB per plane, A4/A6 GRCG controls, and planar byte order. `membus.cpp`: apertures.
- [NP2kai BIOS setup](https://github.com/AZO234/NP2kai/blob/master/bios/bios.c)
  and [work-area definitions](https://github.com/AZO234/NP2kai/blob/master/bios/biosmem.h):
  GRCG/EGC/PEGC capability bits.
- [PC-9800 Technical Databook BIOS](https://pc98.ne.jp/devdocs/pc-9800technicaldatabookbios.pdf),
  chapter 5, printed pages 103-110 and 131-132: high-resolution INT 1Dh, UCW,
  callback, initial mode and display lifecycle.
- [ReactOS video registers](https://doxygen.reactos.org/d6/d70/sdk_2include_2reactos_2drivers_2pc98_2video_8h_source.html):
  mode flip-flops and PEGC MMIO. Its high-resolution plane constants are not used;
  the supplied emulator's shared aperture is the contract used here.

The new tests execute actual NASM and ASW COM instructions under Unicorn, check
independent pixel calculations, bank bounds, palettes, BIOS selection, rejection
and cleanup. DOSBox-X smoke covers both planar page configurations and both
packed binaries. Neither is proof of physical-machine timing or high-resolution
ROM compatibility; those remain untested.

ASW source is generated by `src/make_asw.py` into `src/asw/roto.asm`. It is complete
textual assembly with embedded data and has no NASM dependency at assembly time.
ASW 1.42 Beta build 179 in `E:/aswcurr` and NASM 2.16.03 are the tested assemblers.
Different valid register-to-register encodings mean byte hashes differ. Tests
compare behavior and pixels and run the audio regression against both builds.
